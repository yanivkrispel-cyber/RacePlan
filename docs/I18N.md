# Internationalisation (i18n) + units

RACE PLAN ships in **Hebrew (he, default, RTL)**, **English (en)**, **French (fr)**
and **Spanish (es)**, and can display distances/paces/elevation in **metric** or
**imperial** units. Everything is runtime — no build-time locale split.

## Moving parts

| File | Role |
|------|------|
| `src/i18n.jsx` | `window.I18N` — `t()`, `setLocale()`, `useI18n()` hook, `Intl` wrappers (`fmtNumber`/`fmtDate`), and the **DICTS** object (the four dictionaries; canonical source of truth). |
| `src/units.jsx` | `window.UNITS` — metric↔imperial conversion + formatting (`fmtDist`, `fmtPace`, `fmtElev`, `parseDist`, …) and `setSystem()` / `useUnits()`. |
| boot `<script>` in `web/index.html`, `RacePlan.html`, `build/index.template.html` | Sets `<html lang/dir>` from the resolved locale **before** React mounts (no RTL flash). |
| `web/firebase-init.js` | `saveProfile({locale, units})` persists the choice to `users/{uid}`; `RP_FIREBASE.profile` exposes it back. |

Load order (`build/build.mjs` `JSX_FILES`): `i18n.jsx` → `engine.jsx` → `units.jsx` → everything else.

## How a string is translated

Every UI module has, near the top:

```js
const I18N = window.I18N;
const t = (I18N && I18N.t) || ((k) => k);   // safe fallback for the Node test sandbox
const U = window.UNITS;
```

Then:

```jsx
<button>{t('planner.reset')}</button>
<div>{t('hub.hello', { name: userName })}</div>          // interpolation: "…{name}…"
<span>{t('athletes.segCount', { count: n })}</span>       // plural: key.one / key.other
```

- **Interpolation** — `{tokenName}` in the value, `t(key, { tokenName: … })`.
- **Plurals** — define `key.one` / `key.other` (add `key.two` / `key.few` / `key.many`
  where a locale needs them) and call `t(key, { count })`. `Intl.PluralRules` picks the form.
- **Missing key** — `t()` returns the `en` value if present, else the key string, and
  warns once in the console.
- **RTL/LTR** — never hard-code `direction: 'rtl'`; use `direction: I18N.dir`. Never use
  physical `marginLeft`/`marginRight`/`textAlign:'right'`; use logical
  `marginInlineStart/End`, `textAlign:'start'`. Genuine LTR islands (the seven-seg
  clock, the "RACE PLAN" wordmark, URL inputs, `−10/+10` buttons) keep `direction:'ltr'`.

## Units

The planner engine stays **SI internally** (km, sec/km, m). `window.UNITS` converts only
at the display / input boundary:

```jsx
{U ? U.fmtDist(km) : formatKm(km)}          // "12.3 km" / "7.6 mi", localised number
{U ? U.fmtPace(secPerKm) : formatPace(...)}  // "5:30" against the display unit
U.distUnit()  U.paceUnit()  U.elevUnit()
U.parseDist('12,3')  // → km  (tolerates a locale decimal comma)
```

`ValueEditor` works entirely in **display units** — `planner-b.jsx` converts the value on
open (`U.dispPaceSec` / `U.dispDist`) and back on apply (`U.paceFromDisplaySec` /
`U.parseDist`).

## Locale / unit resolution

1. `?lang=` / `?units=` query param (also persisted)
2. `localStorage['rp-locale']` / `localStorage['rp-units']`
3. signed-in user's `RP_FIREBASE.profile.locale` / `.units` (applied on `ready` when 1+2 absent)
4. `navigator.language` prefix (locale only); imperial default when locale is `en`
5. fallback: `he` / `metric`

The Settings sheet (gear on the Hub, "Settings" in the planner toolbar) writes 1+2 and calls
`saveProfile`. The root `PlannerB` subscribes via `I18N.useI18n()` + `UNITS.useUnits()`, so a
switch re-renders the whole tree live (nothing is `React.memo`'d).

## Adding / changing a string

1. Add the key to **all four** blocks in `DICTS` (`src/i18n.jsx`). The test enforces
   identical key sets and identical `{token}` sets across locales.
2. Use `t('your.key')` in the component.
3. `npm test` — `test/i18n.test.mjs` checks: key parity, placeholder parity, no empty
   values, **every `t('…')` key in `src/` is defined**, no Hebrew literal left outside
   `i18n.jsx`, no physical directional CSS, and that en/fr/es values are not identical to
   their Hebrew source.

## Adding a fifth locale

1. Add the code to `RP_LOCALES` + `RP_LOCALE_NAMES` in `i18n.jsx`, and to `RP_RTL` if it's RTL.
2. Add its full dictionary block to `DICTS` (copy `en`, translate every value).
3. Add the code to the `ok` map in the three HTML boot scripts.
4. `npm test`.

## Not covered (follow-ups)

- Professional native review of the fr/es/en copy (translations are model-generated,
  running-domain-aware, but a native running coach should proof them before public launch).
- User-generated content: race-catalog names show `nameHe` for `he`, the English `name`
  otherwise — no fr/es catalog names. Community submissions likewise.
- SEO: no `hreflang`, no per-locale URLs, single PWA `manifest.webmanifest`.
- On-device layout QA for fr/es (≈15–25 % longer than Hebrew) in the tightest chips.
